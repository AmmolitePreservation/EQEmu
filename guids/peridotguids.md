# peridotguids: the GUID development server

Claude's server for building and testing item GUIDs, apart from Peridot, peridothousing and claudeperidot. Nothing on it is production; it can be rolled back to a snapshot or rebuilt from Peridot at any time.

## The machine

| | |
|---|---|
| Proxmox | VM 145 on labradorite, a full clone of Peridot (VM 104) made 2026-10-26 by a live drive mirror, Peridot's guest filesystem frozen only for the final switch |
| Size | 8 cores, 16 GB; no autostart; tags `eqemu;peridotguids;ubuntu` |
| Disk | `alpha:145/vm-145-disk-0.qcow2`, 350 GB virtual |
| Network | DHCP on `ens18`, MAC `BC:24:11:54:66:96`, reserved `10.111.111.239` on the SonicWall (PeridotGuids); A record `peridotguids.strata.unseencolor.com` on olivine |
| Access | facet host `peridotguids`; Claude's login is Peridot's account, copied to OpenBao `hosts/peridotguids/claude`; SSH host keys and machine-id regenerated on the clone |

Changed from Peridot's copy while its network link was still down (`link_down=1` on net0): the hostname and `/etc/hosts`, the Zabbix agent's `Hostname`, the Zabbix MySQL plugin's address, the Alloy `host` labels, the akk-stack `.env` `IP_ADDRESS`, and the world's `address` and `localaddress` in `server/eqemu_config.json` (`peridotguids.strata.unseencolor.com`; Peridot's say `peridot.unseencolor.com`). The world registers only with the stack's own login server (`127.0.0.1:5998`). The test servers carry no monitoring: the Zabbix agent and Alloy copied from Peridot are stopped and disabled (PRC-5), so the Zabbix and Alloy edits above only keep the copies from naming themselves Peridot. The containers were recreated for the new address; pok and EQBCS, which Peridot runs, are stopped and set not to restart.

## Snapshots

| Snapshot | State |
|---|---|
| `pristine` | The clone set up, the `guids` build running, the database at 9325 / bots 0 / custom 0 with no migration applied; RAM included |
| `ready` | `pristine` plus the claudelink login and character below, camped; RAM included |
| `preGuids` | `ready` plus the full pre-migration seed set below, every character camped; RAM included. **The state TST-3 and TST-6 run from** |

`qm rollback 145 preGuids` (or `ready`, or `pristine`) returns to that running state. A plain reboot also brings the server back by itself: Docker restarts the stack's containers and Spire starts the launcher (`spire.launcher_start` in eqemu_config.json). The containers carried over from Peridot first had to be recreated, since their ports were pinned to Peridot's address (PRC-4).

## The server

The akk-stack at `/opt/eqemu/akk-stack`, Peridot's database as it stood at the clone (dumped first: `backup/peq-2026-10-26-beforeGuids.sql.gz`, 35 MB) and Peridot's quests. The stack's `code/` is a clone of AmmolitePreservation/EQEmu on `guids`, built inside the `eqemu-server` container as the `eqemu` user (`cd ~/code/build && make -j8`, clang, RelWithDebInfo, 161 s; `server/bin` links to `code/build/bin`). The server processes are stopped and started as on peridothousing (`./bin/spire eqemu-server:launcher stop` from a script file, since it kills any shell whose command line names the launcher, then `pkill` of world, zone, ucs, loginserver and queryserv; `launcher start` brings them back).

## The pre-migration seed set (snapshot `preGuids`)

What Peridot's own data holds, as copied (2026-10-26): 2,994 `inventory` rows (1,844 in banks, 28 with augments), 72 `sharedbank`, 81 `guild_bank`, 106 `object` rows with an item, 193 `merchantlist_temp`; nothing in `character_corpse_items`, `character_parcels`, `character_pet_inventory`, `object_contents` or `inventory_snapshots`; no bot tables; `items_evolving_details` has 443 rows, 6 with a required amount. Three facts about what a migration can meet: `trader` is empty at every boot (world's `ClearTraderDetails`); a player's ground drop is never written to `object` (only `#object save` persists one), so `object` rows with an item are static ground spawns; the resale list persists because Peridot sets `World:ClearTempMerchantlist` false (EQEmu's default would clear it at boot), and nothing else on the server empties it (no cron job, no database event, no global quest).

Accounts and characters: `claudeguids` (game account 86) with `Claudeguids` (117, wizard 1, leader of guild SeedGuild, id 2; Peridot's `quests/poknowledge/player.pl` sends an idle guild member in the Plane of Knowledge to the guild hall, so it is found in `guildhall` instance 101 after idling there) and, after `preGuids`, `Kolobe` (120, warrior 1, world 7, SCH-2's creation test) and the soft-deleted `Yoyay-deleted-1793037192` (121, its refused creation); `claudeguidstwo` (game account 87, status 250, OpenBao `services/peridotguids/eqLogin2`) with `Claudeguidstwo` (118, magician 20, skills maxed, Elementalkin: Earth memorized) and `Claudeguidsgone` (119, warrior 1, soft-deleted). `Character:ActiveInvSnapshots` is true in `rule_values`.

Also written: a no-rent Shadowed Long Sword (5101) in Claudeguids' bank slot 2003, a Rusty Short Sword carrying three augments in general slot 32, a Ruined Heretic Longsword with its augment inside the general-slot-1 bag (4013), a hero-model ornament on the tinted cap, and Bone Chips x20 in account 87's shared bank. Cursor-queue items are saved in the cursor-bag range (6010 and up; a bag's slot count is 200 here, so general bags run 4010 to 6009, bank bags from 6210 and shared-bank bags from 11010). Peridot's data has no orphan rows: every inventory, shared-bank, guild-bank, corpse-item and merchant-temp row has its owner and its item number. Of the 107 `object` rows with an `itemid`, one is the seed's static Bone Chips (type 0); the rest are world tradeskill containers whose `itemid` is the container definition the client opens them with, and 46 of those (18 forges of type 15, 7 ovens of type 16, 10 looms of type 21, 11 brew barrels of type 22, in 19 zones) name definitions missing from `items` (17907, 17913, 17914, 17915), a Peridot content gap outside this work. No `object` row holds a player's item: a player's drop is never written, a stored temporary object with an item is removed at zone load, and a static object is content, so the migration leaves `object` alone. Two seed artifacts show in tests: the Ruined Heretic Longsword is lore and the seed wrote a second one into the general-slot-1 bag, so EQEmu's login lore check destroys the worn copy at Claudeguids' first login (its row retires `destroyed`); and the seeded augments are no-drop, which makes every augmented seed item untradeable, so a Bazaar listing with an augment needs one summoned with a tradeable augment (`#summonitem 5013 1 127273`, Moonglow).

Totals at `preGuids`: 3,010 `inventory`, 76 `sharedbank`, 84 `guild_bank`, 4 `character_parcels` with 3 container rows, 2 `character_pet_inventory`, 8 `character_corpse_items` on 2 corpses, 107 `object` rows with an item, 2 `object_contents`, 195 `merchantlist_temp`, 8 `character_evolving_items`, 58 `inventory_snapshots` rows in 5 snapshots.
